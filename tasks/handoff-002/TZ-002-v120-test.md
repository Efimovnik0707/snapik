## 0. Про язык: где спрашивать

Практика: диалог языка в установщике (Inno `[Languages]`) выбирает язык самого установщика, это привычка из 2000-х. Современные десктоп-приложения (Slack, Discord, Notion, Figma, Spotify, CleanShot, Handy) язык не спрашивают вообще: берут из системы, поменять можно в настройках. Спрашивают только там, где локаль ненадёжна, и делают это одним экраном внутри приложения.

Решение:
- Из установщика диалог языка убрать (`installer/SnapBrief.iss:45-47`, `ShowLanguageDialog=no`), установщик сам подхватит язык системы.
- В приложении первый экран мастера «Добро пожаловать» с уже выбранным языком и маленьким переключателем «Русский · English» в углу, не отдельный шаг с двумя большими карточками.
- Правило (языков два): система на русском → русский, любая другая локаль → English. Сейчас `OnboardingWindow.xaml.cs:95-96` маппит uk/be на русский, это убрать.

## A. Установка и первый запуск

### A1. Язык спрашивается дважды
Установщик (`SnapBrief.iss:45-47`) и мастер (`OnboardingWindow.xaml.cs:53,95-96`) не связаны. См. §0.

### A2. Автозапуск спрашивается дважды
Задача `autostart` в установщике (`SnapBrief.iss:51-52,63`) и `StartupBox` в шаге 3 мастера (`OnboardingWindow.xaml:95-104`). Из установщика убрать, оставить только в мастере. Установщик решает только «куда ставить» и «ярлык».

### A3. Мастер: три шага в трёх разных стилях
Шаг 1: карточки 250×104, шрифт 20 (`OnboardingWindow.xaml:80-87`, стиль `LanguageCard` больше нигде не используется). Шаг 2: поле `HotkeyField` 360px (`:89-93`). Шаг 3: чекбокс и ссылка «Показать ярлык» (`:95-104`, `BaseButton` с `Padding=0`, выглядит как ссылка). Шаг 4: вставка на своём фоне `#12161D` (`:108`).

Требование: единый шаблон экрана мастера. Заголовок 21px, подзаголовок 13px приглушённый, контент по центру шириной 360, внизу «Назад / Далее» одинаковой высоты 34. Карточки уменьшить до высоты около 56, шрифт 14, как обычные сегменты. Один фон для всех шагов. Кнопки сейчас слишком большие.

### A4. «Показать ярлык» непонятна
Кнопка открывает Проводник с выделенным SnapBrief.lnk (`OnboardingWindow.xaml.cs:219-239`). Пользователю неясно, зачем. Убрать; вместо неё картинка-подсказка «Пуск → правой кнопкой по SnapBrief → Закрепить на панели задач».

### A5. «Как пользоваться»: расширить
Сейчас одна анимация из 4 сцен по 1.2с (`OnboardingWindow.xaml:27,137-140`). Формат мини-видео нравится, оставить. Сделать 4 таких слайда с точками-пагинацией, по одному на ключевой сценарий:
1. Скриншот по своей клавише → Ctrl+V в чат (текущий).
2. Пачка снимков: несколько захватов подряд → один Ctrl+V вставляет все вместе с комментариями.
3. Комментарии к отметкам: рамка → пилюля → текст → в чат уходит текст с номерами.
4. Лента живёт: снимки остаются, отправленные помечены, «Очистить», когда закончил.

Каждый слайд — Storyboard в том же стиле.

### A6. Лимит пачки
В коде ограничения нет (`EdgeStackWindow.xaml.cs`, счётчик без верхней границы). Требование: максимум **10 снимков** в ленте (буквы A–J). При 11-м захвате тост «В ленте максимум 10 снимков. Отправьте или удалите лишние». В слайде 2 показать «до 10».

## B. Лента снимков (EdgeStackWindow)

### B1. Сессия = запуск приложения, при закрытии снимки удаляются
Сейчас при старте лента восстанавливает прошлую сессию (`EdgeStackWindow.xaml.cs:192-195 LoadCurrentAsync`), в том числе снимок из 1.0.0, а файлы копятся в `%LOCALAPPDATA%\SnapBrief\sessions` без ограничений. Память забивать не нужно.

Требование:
- Запуск приложения = новая пустая сессия. Перезапуск тоже.
- При выходе («Выйти» в трее, «Очистить ленту») снимки сессии удаляются с диска вместе с `exports/revision-*`. Перед этим один диалог: «Снимки этой сессии будут удалены. Чтобы сохранить, нажмите «Сохранить пакет…» в меню •••», кнопки «Удалить» / «Отмена», галочка «Больше не спрашивать».
- Единственный способ сохранить: «Сохранить пакет…» или «Копировать пакет» из «•••».
- Внутри одного запуска правило из ТЗ №1 остаётся: вставка Ctrl+V и чужое копирование ленту не чистят.

### B2. Растягивание по диагонали
Сейчас только левый край (`EdgeStackWindow.xaml:220-223 WidthGrip`). Добавить хват в левом нижнем углу (курсор ↘), меняет ширину и высоту; высота карточек не меняется, растёт видимая часть списка.

### B3. Тень между карточками
Карточки перекрыты на 48px и разделены только рамкой 1px `#46505E` (`EdgeStackWindow.xaml:127-128`), сливаются. У каждой карточки `DropShadow` вниз (BlurRadius 12, ShadowDepth 3, Opacity .5), чтобы читалось как стопка. Механику не менять.

### B4. Крестик на карточке и кнопки шапки
Крестик 27×27 без скругления, только Opacity 0→1 (`:148,167`); кнопки шапки (корзина, •••, ×; `:94-101`) без стиля, дефолтный WPF-шаблон, при наведении бледнеют. Требование: один стиль `IconButton`: 26×26, CornerRadius 8, иконка `#D9DEE8`, при наведении фон `#29303A` и иконка белая (ярче, не бледнее). Крестик на карточке круглый 24px.

## C. Редактор разметки (OverlayEditorWindow, AnnotationCanvas)

### C1. Панель прыгает
Подпись толщины `AppearanceValue.Text` становится пустой для инструментов без штриха (`Appearance.cs:94`), кнопка меняет ширину, панель дёргается. `AppearanceButton` фиксированной ширины (MinWidth около 64), вместо пустого текста «—» или приглушённое «4 px».

### C2. Цвет перекрашивает уже нарисованное
Выбор цвета применяется к выделенному объекту (`Appearance.cs:123-135`), после рисования объект остаётся выделенным, снять выделение кликом по пустому месту нельзя: при активном инструменте клик начинает новый объект, а клик вне снимка = «Готово» (`OverlayEditorWindow.xaml.cs:390-394`).

Требование, механика как в Paint:
- Клик по пустому месту снимка снимает выделение и ничего не рисует. Объект рисуется только жестом «нажать и провести»; одиночный клик без движения объект не создаёт.
- Цвет, толщина, заливка меняют объект только пока он выделен; после клика в пустоту относятся к следующему объекту.
- Карандаш и маркер: свободное рисование, штрих не становится выделенным объектом после отпускания. Двигать или стирать штрих можно, только явно выбрав его инструментом «Выбор».
- Единая механика перемещения: наведение на край (рамка, овал, блюр, заливка) → курсор «лапка», тянем; стрелка, текст, пилюля — наведение на сам объект. Вне объектов курсор обычный указатель (сейчас `Cursor="Cross"` на всём окне, `OverlayEditorWindow.xaml:7`; крестик только при активном инструменте рисования над снимком).
- Esc снимает выделение, не закрывая редактор.

### C3. Толщина: общая настройка, не в стрелке
Толщина есть в поповере (`OverlayEditorWindow.xaml:248-250`) и в меню стрелки (`Arrows.cs:32,46`), отдельная кнопка скрыта (`:201`). Толщина касается и рамок, и стрелок. Требование: рядом с рядом цветов отдельная кнопка «Толщина» с 4 пресетами (2/4/6/8) и ползунком; из меню стрелки толщину убрать; поповер «Цвет» только цвет и заливка.

### C3a. Палитра: стандартная, как в Paint
Текущие 12 цветов (`Appearance.cs:26`) и быстрый ряд из 5 (`:28`) пастельные и нестандартные. Базовый набор как в Paint / macOS Markup: красный #FF3B30, оранжевый #FF9500, жёлтый #FFCC00, зелёный #34C759, голубой #32ADE6, синий #007AFF, фиолетовый #AF52DE, розовый #FF2D55, белый, чёрный, серый #8E8E93, коричневый #A2845E. Быстрый ряд: красный, жёлтый, зелёный, синий, белый. В поповере переключатель «Палитра»: Стандартная / Пастель / Неон, по 12 цветов. Варианты палитр Катя пришлёт отдельно.

### C4. Форма для размытия и скрытия
`Shape` применяется только к Rectangle (`AnnotationCanvas.cs:163-164, 376-383`; маска блюра всегда прямоугольник, `:591`). Blur и Conceal используют ту же форму, что выбрана у фигуры (прямоугольник / скруглённый / овал), маска блюра по форме. Форма запоминается последняя выбранная, общая для фигуры, блюра и скрытия.

### C5. «Скрыть сплошным» = фигура с заливкой
Отдельный инструмент Conceal избыточен. Убрать из «•••». В поповере фигуры заливка получает варианты: **Нет / Цвет 100 % / Полупрозрачно / Размытие**, плюс отдельно цвет рамки и цвет заливки. «Скрыть сплошным» = фигура с заливкой «Цвет 100 %» без рамки. Старые файлы с Conceal читаются как прямоугольник с чёрной заливкой.

### C6. Перо и маркер понятной кнопкой
Сейчас только в меню «•••» текстом без иконок (`OverlayEditorWindow.xaml:202`, `xaml.cs:550-572`), хотя иконки в XAML есть (`:179-190`, Collapsed). На панели кнопка «Карандаш» (split: клик = перо, уголок = перо / маркер) с этими иконками. «•••» после C5 и C6 пустое, убрать.

### C7. Ластик
Удалить объект можно только клавишей Delete (`AnnotationCanvas.cs:255-264`). Инструмент «Ластик» (иконка щётки, клавиша E): клик по объекту удаляет его с Undo; при наведении объект подсвечивается красной рамкой. Delete остаётся.

## E. Темы и внешний вид

Сейчас одна тема `dark` и 4 акцента (`ThemeService.cs:15-18`), фон панелей сплошной `#171A20` 95 % (`EdgeStackWindow.xaml:81`), блюра нет: `AllowsTransparency=True` исключает системный Acrylic.

Набор тем для вкладки «Вид» (фаза 2 из ТЗ №1):
1. **Тёмная** (текущая).
2. **Светлая**: токены уже есть в `SnapBriefTheme.xaml` (Paper / Chrome / Ink).
3. **Как в системе**: следует за Windows.
4. **Матовое стекло**: серая полупрозрачная панель с размытием рабочего стола под ней. На Windows 11 через `DwmSetWindowAttribute(DWMWA_SYSTEMBACKDROP_TYPE, Acrylic)`, это требует отказаться от `AllowsTransparency` и скруглять через `WindowChrome`; на Windows 10 fallback на тёмную с прозрачностью 85 %.
5. **Акценты** отдельным рядом: синий, бирюза, фиолет, коралл, плюс мягкий градиент.

Объём: тени под панелью и карточками (B3), лёгкий градиент на кнопке «Новый снимок», скруглённые иконки (B4). Чёрная непрозрачная лента выглядит тяжело, «стекло» решает это. Конкретные палитры Катя подбирает в мастерской и пришлёт отдельно.
