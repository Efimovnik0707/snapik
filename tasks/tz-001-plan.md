## 1. Что показал разбор кода

Диагнозы ТЗ в основном верны, но в пяти местах картина другая, и это меняет объём работы.

1. **B2 «снимки пропадают» имеет вторую причину, которой в ТЗ нет: импорт.** `ImportFileAsync` (`EdgeStackWindow.xaml.cs:692`) и `ImportClipboardAsync` (`:701`) сбрасывают подготовленный пакет (`InvalidatePrepared`), но не обновляют буфер, в отличие от удаления (`:496`), реордера (`:938`) и восстановления (`:947`). Следующий Ctrl+V не перехватывается (предикат `:83` требует `_prepared != null`), уходит в ветку `:267-272` и вызывает `StartNewSessionAsync`: вставился старый пакет без импортированного файла, панель обнулилась и спряталась. Один дефект объясняет и B2, и B5. Это путь потери данных, чинится первым.
2. **Ротация после вставки уже отложена до следующего захвата** (`:259-265`, `:454-461`, флаг `_pasteObservedForCurrentPackage`), а не мгновенна, как пишет ТЗ. `PasteCoordinator` и транспортный слой о панели не знают, их трогать не придётся.
3. **C4 «показывать клавиши» наполовину выполнен:** буквы уже в тултипах (`OverlayEditorWindow.xaml:91-130`). Реальная проблема другая: почти все тултипы панели разметки отсутствуют в `UiLanguage.cs`, в английском режиме панель остаётся русской. После онбординга с выбором языка (A1) это станет заметно сразу, поэтому пункт поднимается из приоритета 4 в приоритет 1.
4. **C6 уже независим от глобального формата:** формат берётся из расширения выбранного файла (`OverlayEditorWindow.Save.cs:34-35`). Не хватает только WebP, а энкодера WebP в WPF нет.
5. **D7 масштабнее, чем «вынести #2F8CFF»:** в приложении две несвязанные палитры. Словарь `Themes/SnapBriefTheme.xaml:3-13` описывает светлую схему, а все окна нарисованы тёмными инлайновыми литералами (169 hex-значений, из них ~31 акцентных). «Тёмная тема» как ресурсный словарь пока не существует, её нужно извлечь. Из этого же расхождения растёт баг D6.

Ещё две находки, влияющие на все правки редактора (блок C): undo/redo редактора идёт не через `SessionHistory` (класс не используется нигде), а через `OverlaySnapshot` + `AnnotationItem.Clone()` (`EditorModels.cs:65`). Любое новое поле модели, не добавленное в `Clone()`, молча теряется на первом Undo. И аннотации рисуют два независимых метода (`AnnotationCanvas.cs:334` для экрана, превью и Ctrl+S; `WpfExportImageRenderer.cs:82` для пакета), каждый новый вид правится в обоих и получает smoke-проверку пикселя на экспортном PNG.

## 6. Как проверять

Сценарий «Как проверять» из ТЗ остаётся приёмочным, к нему добавляется по каждому коммиту:

- Автоматически: `scripts/build.ps1` (62+ тестов и smoke). Новые обязательные тесты: round-trip `sent` и чтение старого JSON без поля; round-trip `noteOffset`, `shape`, `fill`; `CaptureCropper` сохраняет стикер и пересчитывает offset; шаблон имени `01-A.png`; кламп ширины B6; троттлинг тика B7; `UiLanguage.Apply(editor, "en")` не оставляет кириллицы в тултипах панели; наборы ключей Dark/Light совпадают (D7 фаза 2).
- H1 отдельно: один снимок без заметок → Ctrl+V в Claude Code даёт только картинку, без строки «Снимок A.»; два снимка, заметка только на втором → текст «Снимок B. B1: …» без секции A; снимок без заметок → Ctrl+V в обычное текстовое поле не вставляет пустую строку. H2a: выбрать красный, сделать следующий снимок, рамка красная; перезапуск сохраняет цвет.
- Вручную на чистой учётке Windows после волны 1: установка → мастер (оба языка, своя клавиша, повтор из трея) → три снимка → Ctrl+V в Claude Code → лента на месте, снимки затемнены с галочками, счётчик 0 → четвёртый снимок получает букву A и уходит один → импорт png и webp → в настройках «Сохранить» при наведении темнеет, «Отмена» и крестик слегка светлеют, текст остаётся читаемым.
