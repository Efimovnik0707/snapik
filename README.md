# SnapBrief Project

Локальное Windows-приложение для быстрых заданий агенту: несколько скриншотов, отметки и связанные с ними комментарии, подготовленные к вставке одним действием.

Статус: разработка. Первая Windows-сборка проверена на импорте, разметке, русских заметках и экспорте. Пользователь отклонил её большой оконный редактор; новый основной интерфейс реализован по референсам Casso и Lightshot: разметка поверх экрана и стопка снимков сбоку. В код добавлены размытие, обрезка, отмена/возврат правок и удаление из стопки с восстановлением; новая компоновка ещё ожидает интерактивной проверки. Реальная доставка нескольких вложений и текста в Claude Code и Codex ещё не подтверждена.

После начального выделения можно рисовать отметки. Рамка-аннотация автоматически открывает рядом поле комментария; крестик удаляет заметку. Клик вне снимка или Ctrl+C вне текстового поля сохраняет снимок в стопку и обновляет буфер. Следующий захват дополняет ленту. После Ctrl+V/Alt+V в другом приложении вставленные снимки остаются в ленте: они гаснут, получают галочку вместо буквы и больше не попадают в пакет, а буквы и счётчик считаются по оставшимся. Чужое копирование в буфер ленту не сбрасывает. Правка отправленного снимка возвращает его в пакет; «Очистить ленту» (иконка в шапке или пункт меню «•••») архивирует сессию и открывает пустую.

В основной панели нет выбора получателя. Для Codex Desktop добавлена автоматическая попытка вставить текст следом за изображениями при неизменных окне, фокусе и буфере. Получение текста и нескольких отдельных вложений требует ручной проверки в принимающем приложении; автоматические проверки перечислены в `tasks/verification.md`.

## Запуск и сборка

Ярлык `SnapBrief` на рабочем столе запускает приложение напрямую. Повторный запуск показывает уже работающую стопку. `SnapBrief.cmd` также запускает последнюю опубликованную сборку из `artifacts/publish`. Она автономна и не требует установленного .NET. Папка содержит новый интерфейс со стопкой, размытием и обрезкой; автоматические проверки пройдены, интерактивная приёмка ещё ожидается.

Из корня проекта в PowerShell:

```powershell
# На машине без локального SDK проекта:
& '.\scripts\bootstrap-dotnet.ps1'
# Восстановление зависимостей, тесты и автономная Windows x64 сборка:
& '.\scripts\build.ps1'
```

Если зависимости уже восстановлены, используйте `-NoRestore`. Скрипт останавливается при ошибках тестов или проверки экспорта. Для пересборки сначала закройте работающий SnapBrief. Успешная сборка записывает `artifacts/publish/build-info.json` с результатами проверок и хешами исполняемых файлов.

### Установщик для других пользователей

`scripts\build-installer.ps1` собирает публикацию (те же тесты и smoke, что `build.ps1`) и упаковывает её в `artifacts\installer\SnapBrief-Setup-<версия>.exe` через Inno Setup 6 (`winget install --id JRSoftware.InnoSetup -e`). Установщик ставится без прав администратора в `%LOCALAPPDATA%\Programs\SnapBrief`, создаёт ярлыки в меню «Пуск» и, по желанию, на рабочем столе, умеет добавить автозапуск (галочка снята по умолчанию) и корректно удаляется через «Приложения». Версия берётся из `<Version>` в `src\SnapBrief.App\SnapBrief.App.csproj`. Файл не подписан, поэтому SmartScreen при первом запуске покажет предупреждение («Подробнее» → «Выполнить в любом случае»). Параметры `-NoRestore`, `-SkipTests`, `-SkipPublish` пробрасываются или пропускают этап публикации.

Рабочие сессии хранятся в `%LOCALAPPDATA%\SnapBrief\sessions`. Параметр `--data-dir` позволяет выбрать изолированный каталог; `--demo` создаёт синтетические снимки, `--smoke-test` проверяет экспорт без управления другими приложениями.

При запуске SnapBrief работает в трее без открытой панели. Стопка после захвата показывается спереди без активации и без таймера исчезновения. Крестик скрывает её; успешное завершение пакета при вставке также скрывает стопку. По умолчанию панель держится поверх других окон (в скриншоты она не попадает, окно исключено из захвата экрана); галочка «Поверх других окон» первой в меню «•••» это отключает, выбор запоминается. Крестик скрывает её, сохраняя снимки. Ярлык или значок в трее позволяет снова открыть стопку. Настройки клавиш доступны через трей.

Автозапуск включается и выключается через меню значка в трее → «Запускать с Windows». При входе пользователя запускается канонический EXE в трее. Галочка отражает запись этого экземпляра приложения в автозагрузке текущего пользователя.

## Сохранение снимков

Кнопка дискеты в панели выделения или Ctrl+S открывает сохранение текущего снимка с разметкой в PNG/JPEG. Отмена возвращает к разметке. Сохранение файла не меняет пакет в буфере; комментарии для агента передаются через обычное завершение снимка и вставку.

Меню стопки или трея → «Настройки»: уведомления о копировании/сохранении, запоминание области, захват курсора, очистка ленты после вставки, русский/английский интерфейс, формат PNG/JPEG, качество JPEG и папка быстрого сохранения. На вкладке «Клавиши» команды захвата области и быстрого сохранения всего экрана включаются отдельно. Для записи нажмите поле и затем нужную клавишу или сочетание. Быстрое сохранение по умолчанию выключено; предлагаемое сочетание Shift+Print Screen. Оно сохраняет виртуальный рабочий стол в выбранную папку без добавления в стопку и изменения буфера.

Запомненная область применяется к новому изображению экрана; при изменении расположения или размеров виртуального рабочего стола приложение снова предлагает выделить область. Загрузка, временные ссылки, автокопирование ссылки и прокси относятся к следующему этапу.

## Версия для macOS

Порт на Swift + AppKit + ScreenCaptureKit (macOS 14+) лежит в `macos/`: [macos/README.md](macos/README.md) (установка DMG, разрешения TCC, что проверено), [macos/SPEC.md](macos/SPEC.md) (спецификация порта 1:1 с Windows-кодом), [macos/CONTRACTS.md](macos/CONTRACTS.md), [macos/CORE-API.md](macos/CORE-API.md).

Сборка и проверка идут в GitHub Actions на macOS-раннере (репозиторий `Efimovnik0707/snapbrief`, workflow `.github/workflows/macos-build.yml`): SwiftPM и Xcode, юнит-тесты, `--smoke-test` и `--demo` на собранном `.app`, реальный захват `--capture-test`, сборка `.dmg` и публикация в GitHub Releases (теги `macos-v…`). DMG не подписан Developer ID: первый запуск через правый клик → «Открыть». Интерактивная приёмка на реальном Mac не выполнялась.
